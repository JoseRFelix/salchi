Salchi implementation plan

First-class subagents with Codex desktop parity

A phased plan to move Salchi from flattened subagent events to inspectable, steerable, provider-neutral subagent workflows for Codex and Claude.

Created: 2026-06-19 Scope: apps/server, apps/web, packages/contracts Verification: bun fmt, bun lint, bun typecheck

Executive Summary

Salchi already recognizes some subagent work. Codex collabAgentToolCall items become collab_agent_tool_call, and Claude task or subagent events become generic task.* updates. The missing piece is a first-class subagent model that keeps each child agent visible as an entity with status, role, nickname, source thread, token usage, approvals, and optional steering actions.

The recommended implementation preserves provider-neutral contracts while using provider-specific adapters to recover richer native metadata. Codex remains the lead implementation because app-server already exposes child threads and native subagent fields. Claude follows by mapping SDK task and tool events into the same canonical shape.

Target behavior Users can see active subagents, inspect their summaries, identify which agent raised an approval, and steer or stop supported child agents without losing the clean parent conversation.

Current State

Area Current behavior Gap
Codex adapter Maps collabAgentToolCall to collab_agent_tool_call and routes known receiver thread ids back to the parent turn. Does not model child agents as persisted entities. Native subAgentActivity and child thread metadata are not surfaced as a dedicated UI state.
Claude adapter Classifies Task, agent, and subagent-like tool calls as collab_agent_tool_call. Maps SDK task_started, task_progress, and task_notification to task.*. Task updates are work-log entries, not inspectable child agent records. Tool-use ids, task ids, and parent tool ids are not unified.
Orchestration ingestion Projects item and task runtime events into thread activities. No subagent store, no status coalescing by agent id, and no parent-child relationship exposed to clients.
Web UI Hides task.started, shows progress and completion as work-log rows, and renders subagent tool calls like generic tool cards. No agent list, no thread switcher, no source labels on approvals, and no steer/stop/close controls.

Target Architecture

Provider Native Events

Codex app-server emits collabAgentToolCall, subAgentActivity, child thread metadata, and approvals. Claude SDK emits task messages and tool-use events.

Provider Runtime Events

Adapters normalize native data into subagent.started, subagent.updated, subagent.completed, existing item.*, and existing approval events.

Orchestration and UI

The server stores subagent state per thread. The web app renders an agents panel, source-aware work log rows, and provider-supported steering actions.

Contract Additions

Add provider-neutral subagent events to packages/contracts/src/providerRuntime.ts. Keep existing collab_agent_tool_call item lifecycle events for compatibility.

Event Required payload Optional payload
subagent.started subagentId, parentTurnId, status providerThreadId, sourceItemId, role, nickname, model, prompt
subagent.updated subagentId, status summary, lastToolName, usage, providerThreadId, detail
subagent.completed subagentId, status summary, usage, error
Compatibility rule Do not remove or reinterpret task.* until both Codex and Claude emit reliable subagent.* events. During rollout, emit both where useful and let the UI prefer subagent.* for agent-specific displays.

Implementation Phases

0

Fixture-first discovery

Capture representative Codex app-server events for a prompt that spawns two agents, raises one approval from a child, and completes with a consolidated summary. Capture Claude SDK task events for the same flow.

  • Add red tests for Codex subAgentActivity and child thread metadata.
  • Add red tests for child-origin approvals retaining the child agent label.
  • Add Claude tests for mapping Task tool-use ids to task progress ids.
1

Provider-neutral contracts

Add subagent runtime events and orchestration schemas before touching UI. Include stable ids, parent turn references, provider refs, status, role, nickname, model, summaries, and usage.

  • Create branded RuntimeSubagentId in baseSchemas.ts.
  • Add ProviderRuntimeSubagent* event schemas.
  • Add orchestration activity payloads and persisted detail page fields.
  • Keep schema-only rules in packages/contracts.
2

Codex native mapping

Treat Codex as the reference provider. Build a child-agent registry inside the Codex runtime adapter using collabAgentToolCall.receiverThreadIds, thread parentThreadId, agentNickname, and agentRole.

  • Parse native subAgentActivity lifecycle events.
  • Retain child thread/started metadata before suppressing timeline noise.
  • Attach child agent labels to approvals and user-input requests.
  • Emit subagent.started, subagent.updated, and subagent.completed.
  • Preserve existing parent-turn routing and current flattened work-log behavior.
3

Claude normalization

Map Claude task and tool-use behavior into the same subagent contract without pretending Claude has Codex-style child threads when it does not expose them.

  • Use Claude task_id as subagentId when available.
  • Use tool-use id as a fallback id for Task tool calls.
  • Map task_progress.summary, usage, and last tool into updates.
  • Keep synthetic-turn logic for background task output unchanged.
4

Orchestration state

Store subagents as thread-detail entities instead of only activities. The activity stream remains append-only, while a coalesced subagent map powers the UI.

  • Add subagentIdsByThreadId and subagentByThreadId state.
  • Coalesce updates by subagentId while retaining raw activities.
  • Expose subagents in thread detail responses and recovery resync paths.
  • Ensure reconnects reconstruct active subagents from persisted events.
5

Web UI parity slice

Add a compact agents surface that fits Salchi's existing work-focused UI. Avoid a separate landing page or noisy decorative treatment.

  • Add an "Agents" section near the work log or right panel.
  • Show role, nickname, status, latest summary, token usage, and source item.
  • Let users filter or expand the timeline to one child agent where data exists.
  • Show source agent labels on approvals and user-input prompts.
  • Render completed agents collapsed by default with their final summaries visible.
6

Steer, stop, and close controls

Add controls only after read-only visibility is reliable. Codex should get the first implementation because app-server exposes child thread ids. Claude can expose controls only when the SDK supports equivalent actions.

  • Add provider capability flags for subagentSteer, subagentStop, and subagentClose.
  • Implement Codex steering through the child provider thread when supported.
  • Route cancellation through existing interrupt paths where possible.
  • Require clear disabled states when a provider lacks support.

UX Model

Default view

Parent conversation remains the primary surface. The agents section is a compact operational summary, not a second chat transcript by default.

Expanded view

Opening an agent shows its latest summary, lifecycle history, tool activity, and provider thread id. Transcript-level inspection can be added after event recovery is reliable.

Approvals

Approval prompts include the source agent label and a short source summary. Users should not have to infer which child agent requested a command or edit.

Controls

Steer, stop, and close use icon buttons with tooltips. Unsupported controls remain hidden or disabled based on provider capability flags.

Risks And Mitigations

Risk Mitigation
Event ordering differs between app-server versions. Build idempotent correlation keyed by provider thread id, item id, and task id. Emit placeholder subagents when metadata arrives late, then update them.
Child thread lifecycle changes touch high-risk Effect code. Keep transport and scope ownership unchanged. Add focused regression tests before changing runtime routing.
Claude and Codex expose different levels of control. Model controls as provider capabilities. Visibility is common; steering is provider-specific.
UI becomes noisy for many short-lived agents. Collapse completed agents, show latest summary first, and keep raw event detail in an expandable drawer.

Definition Of Done

  • Codex spawned agents appear as first-class entries with role, nickname, status, final summary, and provider thread id.
  • Claude task/subagent work appears in the same UI shape with graceful omissions for unavailable metadata.
  • Approvals and user-input prompts identify the source child agent.
  • Existing parent timeline behavior and current tests keep passing.
  • Focused regression tests cover Codex child-thread routing, Codex subAgentActivity, Claude task progress, and orchestration recovery.
  • bun fmt, bun lint, and bun typecheck pass.
